Internet protokol a sítě

  • Internet (s velkým I) — globální veřejná síť sítí.
  • internet (s malým i) — obecně propojení více sítí.
  • IPv6 = Internet Protocol version 6 — aktuální „velká“ verze adresování na síťové vrstvě.

IPv4

Standardizován hlavně v RFC 791 (1981). Práce na něm začala koncem 70. let.

232 ≈ 4,3 miliardy adres (ne přesně 4,5).

IPv6

Návrh v 90. letech (drafty kolem 1995–96), klíčová specifikace např. RFC 2460 (1998), dnes RFC 8200.

2128 adres — obrovský adresní prostor.

V 80. letech byly PC doma vzácné; sítě hlavně ve firmách. Provoz byl převážně data (e-mail, text). Dnes dominuje video, plus hlas a data — IPv6 počítalo s větším a rozmanitějším provozem.

Proč vzniklo IPv6

  1. Nedostatek IPv4 adres — prostor ~4,3 mld. nestačí pro všechny zařízení a služby.
  2. Jednodušší a čistší návrh — větší adresy, lepší podpora auto-konfigurace, IPsec jako součást ekosystému.
  3. Růst sítí a typů provozu — nejen textové zprávy, ale video, hlas, IoT, mobilní sítě.

Jak se adresa zapisuje

IPv4

  • Binárně (0/1), v praxi desítkově (0–255).
  • 4 oktety oddělené tečkou.
  • Příklad: 128.164.22.47

IPv6

  • Binárně uvnitř, zápis hexadecimálně (0–9, a–f).
  • 8 hextetů (po 16 bitech) oddělených dvojtečkou.
  • Příklad: 2001:0db8:7654:3210:fedc:ba98:7654:3210

Hextet = 16 bitů = 4 hexadecimální číslice. Jedna hex číslice = 4 bity.

Subnetting / VLSM

U IPv6 je adresní prostor velký, proto je plánování prefixů často přehlednější než u IPv4. Typická délka sítě pro koncové hostitele je /64. Ve výuce se často ukazuje, že se „subnetuje“ mimo jiné ve 4. hextetu (u schémat typu ISP /48 → sítě /64).

Zkracování IPv6

Plný zápis je dlouhý, proto se zkracuje (RFC 5952):

  1. Vynechat úvodní nuly v každém hextetu: 0000 → 0, 0db8 → db8.
  2. Jednou nahradit nejdelší souvislou řadu nulových hextetů znakem :: (při shodě délky bere se levá).
  3. Jeden samotný nulový hextet se nekomprimuje pomocí ::.

Příklad: 0000:1111:0000:2222 → nejdřív 0:1111:0:2222 (a dál podle zbytku adresy).

Důležité: :: smí být v adrese jen jednou. Zápis typu 1222::2222::… je neplatný — není jasné, kolik nul patří kam.

Speciální IPv6 adresy

Adresa / prefix Význam
::1/128 Loopback — localhost (jako 127.0.0.1 u IPv4).
::/128 Unspecified — neurčená adresa (zařízení ještě nemá adresu).
fe80::/10 Link-local — jen na lokálním spoji (ND, automatická konfigurace). V praxi formát fe80::/64 (RFC 4291).
2000::/3 Global unicast — veřejně směrovatelné adresy (rozsah začínající 2000–3fff…).
2001:db8::/32 Dokumentační / výukový prefix (RFC 3849) — do příkladů a učebnic, ne do ostrého internetu.

Jak zařízení získá adresu

IPv4

  • Staticky — správce nastaví ručně.
  • DHCP — server přidělí dynamicky.

IPv6 — 3 běžné způsoby

  • Staticky — ruční konfigurace.
  • SLAAC — bezstavová auto-konfigurace (Router Advertisement + interface ID).
  • DHCPv6 — stavové přidělení ze serveru (případně i DNS info).

Zdroje: RFC 4291, RFC 5952, RFC 3849, RFC 791.

Subnetting

Subnetting IPv6

Jak se dělí adresní prostor — prefixy, /64 a role 4. hextetu.

Základní myšlenka

IPv6 má obrovský prostor, proto je plánování sítí často přehlednější než u IPv4 (VLSM). Koncovým sítím se typicky dává prefix /64 (64 bitů síť + 64 bitů interface ID).

Časté prefixy

  • /48 — organizace / customer (16 bitů na podsítě)
  • /56 — menší blok (8 bitů na podsítě)
  • /64 — jedna LAN / VLAN

4. hextet

U schématu /48 → /64 leží identifikátor podsítě právě ve 4. hextetu (bity 49–64).

Příklad: 2001:db8:abcd:0007::/64
